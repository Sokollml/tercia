## Шаг 1. Проверить, что аккаунт жив

Зайти на [360.yandex.ru/business](https://360.yandex.ru/business) под тем аккаунтом,
с которого подтверждался домен, и посмотреть раздел «Домены» — числится ли там
`tercia.dev` как подтверждённый.

Если да — переходим к шагу 2. Если аккаунт потерян, подтверждение придётся делать
заново: старую `yandex-verification` запись удалить и добавить новую, которую выдаст
панель.

**Про деньги.** Бесплатного тарифа у Яндекс 360 для бизнеса сейчас нет,
[по открытым данным](https://enterno.io/articles/email-on-your-domain) это примерно
от 490 ₽ в месяц за пользователя. Для одного ящика терпимо. Бесплатная альтернатива —
VK WorkSpace, до пяти ящиков, но домен там придётся подтверждать с нуля,
а запись Яндекса — удалять. Раз подтверждение уже есть, дешевле по времени остаться
в Яндексе; если 490 ₽ в месяц не хочется — скажи, распишу переезд на VK.

## Шаг 2. Добавить записи в reg.ru

Личный кабинет reg.ru → домен `tercia.dev` → «Управление зоной DNS».

**Записи A и существующую TXT не трогать.** A держит сайт на GitHub Pages,
TXT — это подтверждение домена. Удалишь — отвалится сайт или подтверждение.

В reg.ru форма добавления записи просит три-четыре поля: **Тип записи**,
**Поддомен**, **Приоритет** (только для MX) и **Значение**. Ниже — что вписывать
в каждую из четырёх записей.

### MX — куда доставлять почту

| Поле формы | Что вписать |
|---|---|
| Тип записи | `MX` |
| Поддомен | `@` |
| Приоритет | `10` |
| Значение (Mail server) | `mx.yandex.net.` |

**Точка в конце `mx.yandex.net.` обязательна.** Без неё панель припишет домен
и получится `mx.yandex.net.tercia.dev` — почта не придёт.

### SPF — кому разрешено писать от имени домена

| Поле формы | Что вписать |
|---|---|
| Тип записи | `TXT` |
| Поддомен | `@` |
| Значение | `v=spf1 redirect=_spf.yandex.net` |

**SPF-запись на домене должна быть ровно одна.** Если позже добавится рассылочный
сервис, запись не дублируется, а объединяется:
`v=spf1 include:_spf.yandex.net include:адрес_сервиса ~all`.

### DKIM — подпись писем

Ключ выдаёт панель Яндекса, он уникальный для домена. В админке:
«Домены» → `tercia.dev` → вкладка «DKIM» → «Подключить DKIM».

| Поле формы | Что вписать |
|---|---|
| Тип записи | `TXT` |
| Поддомен | `mail._domainkey` (панель покажет точное имя) |
| Значение | длинная строка `v=DKIM1; k=rsa; p=…` из панели |

Значение копировать целиком, одной строкой, без переносов. После добавления
вернуться в панель Яндекса и нажать «Проверить».

### DMARC — что делать с письмами, не прошедшими проверку

| Поле формы | Что вписать |
|---|---|
| Тип записи | `TXT` |
| Поддомен | `_dmarc` |
| Значение | `v=DMARC1; p=none; rua=mailto:info@tercia.dev` |

`p=none` — наблюдение без блокировок. Пусть повисит месяц, посмотрим отчёты,
потом можно ужесточить до `quarantine`.

---

### Чего не трогать

Запись `A` держит сайт на GitHub Pages, запись `TXT` с `yandex-verification` —
подтверждение домена. Удалишь любую — отвалится либо сайт, либо подтверждение,
и всё придётся проходить заново.

## Шаг 3. Подождать

Записи расходятся по интернету до 72 часов, обычно — за час-два.
Проверить, не выходя из терминала:

```bash
curl -s -H "accept: application/dns-json" "https://dns.google/resolve?name=tercia.dev&type=MX"
```

Должен появиться `mx.yandex.net.` с приоритетом 10. До этого момента письма
на `info@tercia.dev` будут возвращаться отправителю.

## Шаг 5. Заменить адрес на сайте

**Только после того, как с нового ящика ушло и пришло тестовое письмо.**
Поменять раньше — значит на несколько часов остаться без рабочего контакта
прямо перед рассылкой.

Сейчас `terciaagency@gmail.com` стоит в двенадцати местах на шести страницах:

```
index.html              3   подвал, блок «О нас», форма
dental/index.html       3   подвал, форма
reputation/index.html   1   подвал
portfolio/index.html    1   подвал
privacy/index.html      2   оператор, обращения субъектов
offer/index.html        2   реквизиты, контакты
dpa/index.html          1   обращения по персональным данным
```

Замена делается одной командой — скажи, когда ящик заработает:

```bash
cd ~/tercia-preview/landing && grep -rl "terciaagency@gmail.com" --include="*.html" . | xargs sed -i '' 's/terciaagency@gmail\.com/info@tercia.dev/g'
```

В политике и в приложении о поручении лучше поставить не `info@`, а `pd@` —
чтобы обращения по персональным данным не терялись в общем ящике.

## Шаг 6. Не забыть про gmail

Старый ящик не удалять минимум полгода: на нём висят регистрации в сервисах
и переписка с клиентами, которые знают только его. Настроить в gmail
пересылку на `info@tercia.dev`, чтобы не проверять два ящика.
