# 🗣️ AI Language Tutor Bot

Telegram-бот — ИИ-репетитор иностранного языка. Вы переписываетесь с ботом на
изучаемом языке, а он мягко исправляет ошибки, объясняет их и возвращает вам
типичные ошибки мини-квизами по алгоритму интервальных повторений.

> Пет-проект для портфолио: aiogram 3, чистая доменная логика с тестами,
> SQLite локально / PostgreSQL в проде, LLM через OpenAI-совместимый API.

## Что делает

- **Живое исправление.** Вы пишете сообщение на изучаемом языке — бот отвечает
  на нём же (поддерживая диалог) и, если есть ошибки, показывает исправленную
  версию + короткое объяснение на языке интерфейса.
- **Копит ошибки.** Каждая реальная ошибка сохраняется как карточка для
  повторения с типом (грамматика, времена, артикли, предлоги, лексика и т. д.).
- **Возвращает по интервалам.** Команда `/quiz` поднимает «созревшие» ошибки:
  правильный ответ раздвигает интервал повторения, неправильный — сбрасывает,
  чтобы карточка вернулась быстрее (SM-2 lite / Leitner).
- **Напоминает.** Планировщик раз в день пингует пользователей, у которых
  накопились ошибки к повторению.
- **Статистика.** `/stats` показывает прогресс и топ типичных ошибок.
- **Два языка интерфейса** — русский и английский.

## Возможности (MVP)

| Область | Что реализовано |
|---|---|
| Онбординг (FSM) | выбор языка интерфейса → изучаемого языка → уровня CEFR (A1–C1) |
| Диалог (FSM) | анализ сообщения через LLM, строгий JSON-разбор с fallback на «мусор» |
| Квиз (FSM) | очередь созревших ошибок, показ ответа, самооценка, обновление интервала |
| Интервальные повторения | `app/srs.py` — чистый SM-2 lite, покрыт тестами |
| Хранилище | `users` / `mistakes(next_review)` / `sessions`, SQLite и PostgreSQL |
| Лимиты | дневной лимит бесплатных исправлений + rate-limit на пользователя |
| Надёжность | валидация, обработка ошибок LLM/сети, логирование |
| i18n | RU/EN интерфейс (`app/i18n.py`) |

## Команды бота

- `/start` — выбрать язык интерфейса, изучаемый язык и уровень
- `/quiz` — повторить накопленные ошибки
- `/stats` — прогресс и типичные ошибки
- `/cancel` — прервать текущий диалог или квиз
- `/help` — справка

## Архитектура

```
app/
  bot.py          — бутстрап: сборка бота, DI, планировщик, polling
  config.py       — конфиг из переменных окружения (.env)
  db.py           — абстракция БД: SqliteDatabase / PostgresDatabase
  repository.py   — весь SQL, driver-agnostic, возвращает dict'ы
  srs.py          — интервальные повторения (SM-2 lite) — чистая логика
  llm.py          — OpenAI-совместимый клиент + строгий разбор JSON-ответа
  services.py     — чистые помощники по времени/таймзонам
  i18n.py         — RU/EN тексты интерфейса
  keyboards.py    — inline-клавиатуры и протокол callback-data
  states.py       — FSM-группы (Onboarding / Dialog / Quiz)
  middlewares.py  — DI + rate-limit (ядро лимитера — чистое, тестируемое)
  scheduler.py    — APScheduler: ежедневные напоминания
  handlers/       — onboarding, dialog, quiz, stats, common
db/
  001_init_sqlite.sql / 001_init_postgres.sql — схема
tests/            — pytest (интервалы, разбор LLM, репозиторий, лимитер, i18n, smoke)
```

Принцип: доменная логика (`srs`, `llm`-парсер, `services`, лимитер, `i18n`) не
зависит от aiogram и сети — поэтому быстро и полно покрывается юнит-тестами.
Сетевые/фреймворковые импорты ленивые, так что весь пакет импортируется в тестах
без запуска бота.

### Совместимость Python

- **Локально:** Python 3.9 (`from __future__ import annotations`, `Optional`/`List`
  из `typing`, без PEP 604-юнионов в рантайме).
- **Docker:** `python:3.12-slim`.

## Быстрый старт (локально, SQLite)

```bash
# 1. Клонировать и войти в папку проекта
cd 12-bot-language-tutor

# 2. Виртуальное окружение и зависимости
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt      # для запуска бота хватит requirements.txt

# 3. Настроить окружение
cp .env.example .env
#   Впишите BOT_TOKEN (от @BotFather) и LLM_API_KEY.
#   DB_DRIVER=sqlite уже задан по умолчанию.

# 4. Запуск
python main.py
```

Схема БД применяется автоматически при старте. Локальный SQLite-файл — `tutor.db`.

> ⚠️ Если проект лежит на внешнем диске (exFAT/сетевой), создавайте `.venv` на
> локальном диске: macOS плодит `._*.pth` файлы, которые ломают загрузчик venv.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты проверяют, в частности, что `next_review` **растёт** с каждым верным
ответом и **сбрасывается** при ошибке (`tests/test_srs.py`,
`tests/test_repository.py`).

## Запуск в Docker (PostgreSQL)

```bash
cp .env.example .env         # впишите BOT_TOKEN и LLM_API_KEY
docker compose up --build
```

`docker-compose.yml` поднимает PostgreSQL 16 и бота; переменные `DB_DRIVER`,
`DB_HOST`, `DB_PORT` для контейнера бота проставляются автоматически, так что
локальный `DB_DRIVER=sqlite` из `.env` не мешает.

## Деплой

- **Один контейнер + управляемый PostgreSQL.** Соберите образ из `Dockerfile`,
  задайте переменные окружения (см. `.env.example`), укажите `DB_DRIVER=postgres`
  и реквизиты managed-базы. Бот работает через long-polling — входящие порты не
  нужны.
- **Docker Compose / VPS.** `docker compose up -d --build` — бот и база рядом,
  данные Postgres в volume `pgdata`.
- **Масштабирование.** FSM-состояния хранятся в памяти (`MemoryStorage`); для
  нескольких инстансов замените на Redis-хранилище aiogram.
- **Таймзона** (`TZ`) влияет на сброс дневного лимита и время напоминаний.

### Переменные окружения

Все ключи описаны в [`.env.example`](.env.example): `BOT_TOKEN`, `DB_*`,
`LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`, `TZ`, лимиты и `LOG_LEVEL`.
LLM-эндпоинт — любой OpenAI-совместимый (`/chat/completions`).
