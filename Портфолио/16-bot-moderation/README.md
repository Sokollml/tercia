# 🛡️ Telegram-бот модерации сообществ

Бот для модерации групп и супергрупп в Telegram: капча для новичков,
антиспам и антифлуд, инструменты модерации (`/warn`, `/mute`, `/ban`) с
эскалацией по порогу предупреждений, журнал действий и настраиваемые тексты.
Написан на **aiogram 3**, работает с **PostgreSQL** (прод) или **SQLite** (локально).

> Пет-проект для портфолио. Чистая логика модерации отделена от Telegram-слоя и
> покрыта тестами.

## ✨ Возможности

- **Welcome + капча.** Новичок ограничивается в правах и решает мини-капчу
  (арифметика, кнопки-варианты) за `N` секунд. Не успел или ответил неверно —
  кик. Ожидающие капчи хранятся в БД и переживают перезапуск бота.
- **Антиспам.** Удаление сообщений со ссылками, пересланных сообщений и
  сообщений со стоп-словами. Каждый фильтр включается отдельно.
- **Антифлуд.** Скользящее окно «`N` сообщений за `M` секунд» → авто-мут.
- **Модерация.** `/warn`, `/mute`, `/unmute`, `/ban`, `/unban`, `/kick`.
  При достижении порога предупреждений (`warn_limit`) пользователь
  автоматически получает мут, а счётчик варнов сбрасывается.
- **Журнал действий.** Все действия модерации пишутся в `action_log`,
  просмотр — `/log`.
- **Правила и тексты.** `/rules`, настраиваемые `/setrules` и `/setwelcome`.
- **Настройки чата.** `/settings` — обзор, `/set <параметр> <значение>` —
  правка модулей и порогов. Список изменяемых параметров ограничен
  белым списком (защита от SQL-инъекций через имя колонки).
- **Права и безопасность.** Whitelist владельцев бота (`ADMIN_IDS`),
  проверка прав администраторов чата, проверка собственных прав бота перед
  ограничением/баном, rate-limit входящих апдейтов на пользователя.
- **RU/EN.** Язык переключается на чат (`/lang ru|en`), тексты локализованы.

## 🧩 Команды

| Команда | Описание |
|---|---|
| `/start`, `/help` | Справка |
| `/rules` | Показать правила чата |
| `/warn` | Предупреждение (ответом на сообщение) |
| `/mute [минуты]` | Заглушить пользователя |
| `/unmute` | Снять заглушку |
| `/ban`, `/unban <id>`, `/kick` | Бан / разбан / удаление |
| `/warns` | Счётчик активных предупреждений |
| `/log` | Последние действия модерации |
| `/settings`, `/set <параметр> <значение>` | Настройки чата |
| `/setrules <текст>`, `/setwelcome <текст>` | Тексты правил и приветствия |
| `/lang ru\|en` | Язык бота |

## 🔑 Права администратора для бота

Добавьте бота в группу и выдайте ему права **администратора**:

- **Ограничение участников** (`can_restrict_members`) — для капчи, мутов и банов;
- **Удаление сообщений** (`can_delete_messages`) — для антиспама;
- **Бан пользователей** — для `/ban` и кика по таймауту капчи.

Без права «Ограничение участников» бот сообщит об этом и не будет применять
модерацию. Владельцы из `ADMIN_IDS` считаются администраторами всегда.

## 🏗️ Архитектура

```
app/
  config.py        # конфиг из переменных окружения
  db.py            # абстракция БД: SQLite и PostgreSQL за единым API
  dbsetup.py       # применение схемы из db/*.sql
  repository.py    # слой доступа к данным (весь SQL здесь)
  moderation.py    # ЧИСТАЯ логика: капча, фильтры, антифлуд, эскалация (тесты)
  i18n.py          # RU/EN тексты
  keyboards.py     # инлайн-клавиатуры капчи
  utils.py         # проверки прав и безопасные обёртки Bot API
  middlewares.py   # rate-limit входящих апдейтов
  scheduler.py     # APScheduler: кик по таймауту капчи
  handlers/        # хендлеры aiogram (common, captcha, antispam, commands, settings)
  bot.py           # сборка и запуск
db/
  001_init_sqlite.sql
  001_init_postgres.sql
tests/             # pytest: логика, репозиторий, эскалация варнов, таймаут капчи
```

Модель данных: `chats` (настройки на чат), `warnings`, `mutes`,
`captcha_pending`, `action_log`. Время хранится как UNIX-секунды, флаги — `0/1`,
поэтому один и тот же SQL работает на обоих драйверах (в PostgreSQL `?`
переписывается в `$1, $2, …`).

## 🚀 Запуск локально (SQLite)

Требуется Python 3.9+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# впишите BOT_TOKEN (от @BotFather) и, при желании, ADMIN_IDS

python -m app
```

По умолчанию используется SQLite (`moderation.db`), схема применяется
автоматически при старте.

## 🐳 Запуск в Docker (PostgreSQL)

```bash
cp .env.example .env
# впишите BOT_TOKEN; DB_DRIVER/DB_HOST для контейнера уже заданы в compose

docker compose up --build -d
docker compose logs -f bot
```

`docker-compose.yml` поднимает PostgreSQL и бота; данные БД сохраняются в
volume `pgdata`.

## 🧪 Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Покрыто: решение и проверка капчи, детектор ссылок и стоп-слов, антифлуд,
формат длительности, **эскалация варнов → мут при достижении порога**,
**кик новичка по таймауту капчи**, а также smoke-import всех модулей.

> Примечание: если каталог проекта содержит не-ASCII символы в пути,
> создавайте виртуальное окружение в каталоге с ASCII-путём — это ограничение
> `venv`, а не проекта.

## ✅ Чек-лист перед запуском в проде

- [ ] Создан бот у @BotFather, `BOT_TOKEN` в `.env`.
- [ ] В @BotFather отключён Privacy Mode (иначе бот не видит сообщения группы).
- [ ] Бот добавлен в группу и назначен администратором.
- [ ] Выданы права: ограничение участников, удаление сообщений, бан.
- [ ] Заданы `ADMIN_IDS` (владельцы бота).
- [ ] Для прода: `DB_DRIVER=postgres` и параметры подключения к БД.
- [ ] Проверены пороги: `CAPTCHA_TIMEOUT`, `WARN_LIMIT`, `MUTE_DURATION`,
      `ANTIFLOOD_LIMIT`/`ANTIFLOOD_WINDOW`.
- [ ] Настроены правила (`/setrules`) и приветствие (`/setwelcome`).
- [ ] `pytest` зелёный.
