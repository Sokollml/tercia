# Портфолио агентства — единый мастер-документ (промпты для Claude Code)

Все направления в одном файле: **WordPress, лендинги, Telegram-боты и ИИ-ассистенты, боты для сообществ, mini-apps, автоматизации на n8n.** Аудитория — Россия и США (тексты двуязычные RU/EN). Все промпты готовы к вставке в Claude Code.

## Правила
- По одному проекту за раз, каждый — отдельный репозиторий. Не проси всё сразу.
- Тебе НЕ нужны все 22 сразу. **6–8 сильных с живыми демо** уже делают убедительное портфолио. Остальные добивай параллельно с первыми заказами.
- В демо честно помечай, что данные вымышленные, и не выдавай их за клиентские кейсы.
- В каждом промпте: реальные тексты (не lorem, RU+EN), README на русском, НЕ дефолтный ИИ-дизайн.

## Инфраструктура (важно для автоматизаций и ИИ-ассистентов)
У тебя **n8n уже развёрнут на VPS** (Docker + Postgres). Поэтому:
- Claude Code **не поднимает свой n8n** — он генерит **workflow-JSON**, который ты импортируешь (Import from File, один клик).
- Сложную логику Claude Code выносит в **Code-ноды** или **отдельные микросервисы** (HTTP), которые воркфлоу дёргает.
- Промпты для AI Agent нод — отдельными файлами, ты вставляешь их в ноды.
- БД — Claude Code пишет SQL-миграции, ты накатываешь на свой Postgres.

**Идея:** движок викторин для чата — по расписанию кидает вопрос с вариантами, считает очки, ведёт таблицу лидеров. Использует нативные quiz-опросы Telegram.

```
Ты — бэкенд-инженер. Построй Telegram-бота викторин для сообществ (портфолио).

ЧТО ДЕЛАЕТ:
- По расписанию (или по команде админа) публикует вопрос викторины в чат
  через нативный Telegram quiz poll (с правильным ответом)
- Считает очки участникам за правильные ответы, ведёт таблицу лидеров сезона
- Банк вопросов по темам/категориям (админ пополняет командами или импортом)
- Режимы: ежедневный вопрос / марафон (серия вопросов подряд) / блиц
- Итоги сезона с поздравлением победителей

СТЕК: Python + aiogram 3, PostgreSQL, планировщик.

ТРЕБОВАНИЯ:
- Модель: questions (текст, варианты, правильный, категория), quizzes,
  answers, scores, seasons
- Учёт ответов через quiz poll (обработка poll_answer), защита от повторного
  ответа, начисление с учётом скорости (опц.)
- Админ-команды: добавить вопрос, запустить викторину, сброс сезона
- Мультиязычность RU/EN, обработка ошибок, логирование, .env.example

ДЕПЛОЙ: docker-compose, VPS/Railway, @BotFather, как добавить в группу.
```

## 19. Mini-app поиска фриланс-заказов (React + n8n)

**Архитектура (под твой n8n на VPS):**
```
Collector (Telethon userbot, отдельный сервис) → Postgres (сырые сообщения)
     → n8n workflow (ИИ-классификация + скоринг) → Postgres (заказы)
     → n8n webhooks (API для mini-app) → React mini-app (Vercel)
```
Userbot читает чаты и **не живёт в n8n** (n8n про ботов, а не про MTProto-аккаунт) — это отдельный сервис. n8n берёт классификацию и API.

```
Ты — фулстек-инженер. Построй Telegram mini-app для поиска фриланс-заказов.
У меня уже есть n8n на VPS (Docker + Postgres) — используй его для
ИИ-классификации и как API-слой (вебхуки), не поднимай параллельную
инфраструктуру. Userbot-сборщик сделай отдельным сервисом.

АРХИТЕКТУРА:
1. collector/ — Python + Telethon (userbot), читает заданные публичные чаты,
   пишет сырые сообщения в Postgres. ТОЛЬКО чтение.
2. n8n workflow (JSON для импорта) — классификация и скоринг.
3. n8n webhooks (JSON для импорта) — API для mini-app.
4. miniapp/ — React + Vite + TS + @twa-dev/sdk для Vercel.

--- COLLECTOR ---
БЕЗОПАСНОСТЬ АККАУНТА (в README крупно):
- Только чтение. Никакой автоотправки в чаты — спам и бан.
- Отдельный аккаунт и номер, не основной.
- FloodWaitError, троттлинг, только чаты, куда вступил вручную.
- Сессия Telethon в volume, не в репозитории.
Логика: слушает новые сообщения в чатах из config.yaml → префильтр по
ключевым/стоп-словам (без ИИ) → дедуп по хешу → запись в raw_messages
(статус «на обработку»). Плюс скрипт разовой выгрузки истории для теста.

--- n8n КЛАССИФИКАЦИЯ (workflows/classify.json) ---
Schedule Trigger (раз в N минут) → необработанные raw_messages → AI Agent
(строгий JSON: is_order, service_type, summary, budget, urgency, languages,
skills_required) → таблица orders → пометить обработанным. Мусорный JSON →
fallback на ручную проверку. prompts/order_classifier.txt.

--- n8n API (workflows/api.json) ---
Webhook-ноды как эндпоинты (все с проверкой initData-подписи):
- список заказов с фильтрами (навыки, ключевые слова, мин.бюджет, языки,
  тип услуги, период) + пагинация
- получить/обновить настройки пользователя
- сменить статус заказа (интересует/скрыт/откликнулся)
Валидацию initData (HMAC Telegram) вынеси в Code-ноду/микросервис, через
который идут все запросы. Без валидированного пользователя API не отвечает.

--- MINI-APP ---
Экраны:
1. Лента заказов — карточки: тип услуги, бриф, бюджет, срочность, score
   совпадения с моими настройками, чат-источник, время. Сортировка по
   score/дате, бесконечная прокрутка.
2. Мои настройки — навыки (мультивыбор), ключевые слова, мин.бюджет, языки,
   типы услуг. Per-user, влияют на score и фильтры.
3. Карточка заказа — полный текст, поля, «Открыть в Telegram» (deep link),
   статусы, заметка. Отклик пользователь пишет САМ вручную — mini-app НЕ
   отправляет сообщения за него.
UX: нативные MainButton/BackButton, haptic, тема TG, мобильный UI,
пустые/загрузочные состояния, дизайн с характером (не дефолтный ИИ-дизайн).

МОДЕЛЬ (db/001_orders.sql):
raw_messages (id, chat, author, text, text_hash UNIQUE, status, created_at)
orders (id, source_chat, author_username, raw_text, service_type, summary,
  budget, urgency, languages, skills_required, message_link, created_at)
users (tg_id, settings jsonb, created_at)
user_order_status (user_tg_id, order_id, status, note)

ПРОМПТ (prompts/order_classifier.txt):
Ты — аналитик фриланс-заказов. Определи, заказ ли это (ищут исполнителя).
Ответь СТРОГО одним JSON без markdown:
{"is_order": true/false, "service_type": "...|null", "summary": "бриф своими
словами", "budget": "число|null", "urgency": "low|medium|high",
"languages": ["ru","en"], "skills_required": ["..."]}
is_order=false для резюме исполнителей, рекламы, обсуждений. Чего нет — null.

ДЕПЛОЙ:
- collector и микросервис валидации → docker-compose, на VPS рядом с n8n
- фронт mini-app → Vercel
- воркфлоу n8n → импортирую JSON
- .env.example: TG_API_ID, TG_API_HASH, TG_PHONE, BOT_TOKEN, MINIAPP_URL,
  DB_*, LLM; где взять api_id/api_hash (my.telegram.org)
- инструкция: авторизация сессии Telethon, привязка mini-app к боту
  (@BotFather), какие credentials создать в n8n

КАЧЕСТВО: тесты (initData, префильтр, дедуп, парсинг JSON), README на русском
со схемой (mermaid), предупреждением про бан-риски и пошаговой сборкой.

ЭТАП 0: покажи MVP-скоуп, модель данных, экраны, список n8n-воркфлоу
и credentials. Если не отвечаю — по дефолтам.

После генерации: запусти collector на тестовой выгрузке истории, прогони
классификацию, покажи mini-app с лентой и настройками, выведи чек-лист.
```

1. **Это ближе к продукту, чем к инструменту.** «Пользователь выбирает настройки» → если пустишь других людей, появятся модерация, нагрузка на userbot, приватность, монетизация. 3. **Отклик всегда вручную** из своего аккаунта. Автоотправка = бан + минус репутации, и без персонализации не работает.

| Автоматизации (n8n) | твой VPS (уже есть) | скрин схемы + видео прогона |

| Слой | Claude Code | Ты руками |

| Mini-app фронт, лендинги | весь код | деплоишь на Vercel |

| Сессия Telethon | код авторизации | проходишь вход один раз |

**Три вещи важнее кода:**

2. **Живые демо-боты** — ссылку `t.me/бот` кидаешь в переписку, тыкают за 10 сек. Для ботов сообществ — заведи **тестовый чат** и покажи бота в деле (welcome, XP, лидерборд).
3. **Одна ссылка на витрину** + Pin всех репозиториев в профиле GitHub.

**Не экономь на хостинге ботов/mini-apps** (кроме n8n-ботов, они на твоём VPS). Бесплатные тарифы усыпляют сервис → демо «не отвечает» → выглядит сломанным.
